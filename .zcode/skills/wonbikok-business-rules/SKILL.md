# 원비콕 비즈니스 규칙 참조

## 이 스킬의 목적

원비콕의 모든 비즈니스 규칙은 PRD.md **22장 Rule ID 체계**로 관리된다. Developer·Reviewer·Tester는 코드 작성·검증·시나리오 도출 시 이 Rule ID를 참조 키로 사용한다. 원문 규정(수용조건·상세 명세)은 반드시 PRD.md 해당 장을 확인한다 — 본 스킬은 색인이다.

## Rule ID 네이밍

형식: `{도메인 접두어}-{3자리 숫자}`. ID는 절대 재사용하지 않고(폐기 시 결번), 추가는 마지막 번호+1, 하나의 ID는 하나의 검증 가능한 규칙만 기술한다.

| 접두어 | 도메인 | 대상 |
|:---|:---|:---|
| TEN | 테넌시·개인정보 | 데이터 격리, 개인정보 보호 |
| INV | 청구(Invoice) | 월간 청구 생성·확정·취소 |
| PAY | 수납(Payment) | 입금 확인·정정 |
| CR | 현금영수증(CashReceipt) | 발행·취소·멱등 |
| MSG | 메시지(MessageLog) | 알림톡·SMS 발송·리마인더 |
| LNK | 학부모 공개 페이지(Link) | 청구 링크 보안 |
| SUB | 구독(Subscription) | 플랜·결제·체험 |
| ADM | 관리자 콘솔 | 운영 조치·감사 |

## 핵심 규칙 요약 (전체 목록은 PRD.md 22장)

**테넌시·개인정보 (TEN)** — Tenant 단위 데이터 격리 + 서버측 권한 검증 / 주민등록번호 수집 금지(소득공제=휴대폰번호, 지급증명=사업자번호) / 식별정보 저장 암호화 + 목록 마스킹 / 청구·거래 이력은 스냅샷 저장(원비 설정 변경이 과거 값 바꾸지 않음).

**청구 (INV)** — 원생×당월 중복 청구 생성 금지 / 확정 후 수정은 변경 사유 기록 / 취소 청구는 수납 합계에서 제외 / 휴원·퇴원원생은 생성 대상 제외 / 부분납은 잔액 표시 상태 구분.

**수납 (PAY)** — 완납 처리된 청구의 재완납 차단 / 수납 등록·정정에 처리자·시간 기록 / 정정은 삭제가 아닌 취소·정정 이력.

**현금영수증 (CR)** — 발행 유일성: 원생×당월×발급유형(멱등, 내부 ID↔공급자 키 연결) / 자동발행 트리거는 '입금 확인'뿐 / 공급자 최종 상태 확인 전 성공 표시 금지 / 재시도 전 공급자 상태 조회로 중복 방지 / 취소는 원본 발행과 연결 / 이력 5년 보관 / 실패 시 원장에게 이중 알림.

**메시지 (MSG)** — 발송 유일성: 원생×당월×템플릿 유형 / 알림톡 실패 시 SMS/LMS 대체 발송 필수 / 자동 재시도 무한 반복 금지 / 리마인더 제외 설정 즉시 반영 / 발신자 표기는 원장 채널·번호 기준 / '다시 보내기' 예외는 이력 기록.

**학부모 공개 페이지 (LNK)** — 예측 불가능한 공개 토큰 URL / 타 청구·원생 명단·내부 정보 노출 금지 / URL에 개인정보 직접 포함 금지 / 만료·폐기 링크는 정보 미표시 + 원장 문의 안내 / 접근 로그 기록.

**구독 (SUB)** — 플랜 원생 수 상한 초과 시 신규 등록 차단(기존 데이터 유지) / 결제 실패 3회 재시도 후 서비스 일시정지(데이터 유지·조회 허용) / 미결제 시 30일 데이터 보관 후 삭제 예정 안내 / 과금 통지는 알림톡+앱 배너 이중 전달.

**관리자 (ADM)** — 파괴적 조치는 사유 입력 필수 + 감사 로그 영구 보존 / 개인정보는 기본 마스킹 / 발행 재조치는 '원장 확인 후' 원칙(서버 문제 예외만 사유와 함께) / 설정 변경은 2단계 확인(미리보기→확정).

## 데이터 흐름 3대 정산 규칙 (정합성)

원장 앱 리포트 수치 = 관리자 발행 대장 수치 = 실제 공급자(포트원) 처리 건수. 월 1회 자동 대조 배치로 검증, 불일치 시 운영자 알림.

## 외부 연동 전제

- 현금영수증 = 포트원 현금영수증 API (**외부 결제건[계좌이체] 발급 경로** — PG 결제 아님)
- 알림톡/SMS = 솔라피 Messages v4 (자동 대체발송 설정)
- 연습 모드(practice)에서는 실발송·실발행 금지.
