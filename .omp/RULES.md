# RULES — 원비콕 하네스 스티키 강제 규칙

컨텍스트 압축 후에도 반드시 유지되는 규칙이다. HARNESS_CONVENTION.md(v3.2.0)와 본규칙이 충돌하면 규약이 우선한다.

1. **사용자 승인 게이트 (§6.13)**: 오케스트레이터는 사용자 승인 전 어떤 에이전트도 스폰하지 않는다. 플랜 요약 보고 후 턴을 종료하고 승인을 기다린다. `progress.json`의 `currentPhase`가 `awaiting_approval`인 상태에서는 플랜 재보고 후 승인 대기만 한다. 승인 후에는 재승인 없이 파이프라인을 자동 진행한다.
2. **오케스트레이터 직접 구현 금지**: 코드 수정은 모두 Developer 에이전트에게 위임한다. 오케스트레이터는 통제·검증·보고만 수행한다.
3. **문서 선행 (Phase 2)**: PRD.md/AGENTS.md 현행화는 구현보다 먼저. "수정 사항 없음"은 허용되지 않는다(최소한 진행 상황 표 갱신).
4. **일회성 스폰 (§4.6)**: 작업 위임마다 task tool로 신규 스폰. 완료 보고를 낸 에이전트의 재소환 금지. 최종 결과 수신 후 즉시 등록 해제를 시도한다.
5. **Rule ID 필수**: 비즈니스 로직 구현·리뷰·테스트는 PRD.md 22장의 Rule ID를 반드시 참조·인용한다.
6. **품질 게이트**: 커밋 전 `bin/rubocop`(0 에러) + `bin/brakeman`(0 경고) + `bin/rails test`(통과). 외부 API(포트원·솔라피) 실호출 테스트 금지.
7. **경로 불변**: `.omp/progress.json`과 `_workspace/` 위치는 변경하지 않는다.
